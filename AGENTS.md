# Agent instructions: Release Atlas

## Product and architecture

Release Atlas helps software maintainers review upgrade evidence. It connects versioned source text, declared application usage, cited findings, technical identifiers and human review decisions.

- Backend: Python, FastAPI, SQLite, scikit-learn and NetworkX.
- Frontend: React, TypeScript and CSS. Edit frontend sources, then rebuild the self-contained HTML with `npm run build`.
- `backend/models.py` defines validated data contracts; `backend/store.py` owns persistence and revision checks; `backend/nlp.py` implements analysis and retrieval; `backend/providers.py` implements model adapters.
- Documentation NLP: `backend/document_parser.py` builds exact-span Markdown/RST paragraphs, list items, code and tables with heading paths. `backend/document_classifier.py` uses local normalized 48-dimensional TF-IDF/LSA embeddings plus logistic regression for documentation purposes, with abstention, competing labels and nearby synthetic training examples. Keep release-change labels separate from purpose. `backend/technical_entities.py` supplies typed syntax rules with exact-case source spans, normalized matching keys and explicit rule names. Never execute document code or render it as HTML.
- `backend/nlp.py` orchestrates structure, purpose classification, NMF prose topics, typed entities and existing graph/conflict/retrieval behavior. Topic terms are learned from prose, not copied headings; code/URLs are excluded. Tiny/repetitive inputs must not force topics. Topic selection filters actual membership. `Claim.document` and `Analysis.pipeline` are optional extensions so legacy snapshots remain readable; reanalyze to populate them. Validate entity spans against immutable source text and topic representatives against their members. Preserve review IDs for unchanged exact passages; regrouping can invalidate old identities.
- `frontend/PipelineExplorer.tsx` exposes four numbered stages, document map, purpose counts, weighted topics/representatives, searchable typed inventory, inspectable per-passage methods and evaluation limits. `frontend/pipeline.ts` composes section/source/purpose/entity/topic filters; original review/search/release filters remain available. Pipeline state is browser-local and resets across workspaces/imports/reanalysis. Hosted/tutorial/saved views inspect prepared outputs only and must not call live APIs. Source text and metadata must remain escaped.
- `backend/calculator.py` implements the read-only OpenAI function `calculate`: bounded decimal arithmetic and ordered semantic quantity events, with no eval, shell, file or network access. Consumption/removal/loss/decrease subtract positive amounts; addition/receipt/increase add. Negative event amounts and impossible negative inventory are rejected. Keep strict schemas, current citation-ID allowlists, explicit rounding, a shared three-tool-call/four-request limit and one overall provider timeout. Pass model output items and matching function_call_output items back statelessly with store=false. Do not add arbitrary execution tools. Non-OpenAI adapters remain text-only.
- `backend/source_actions.py` implements Ask Atlas's only write-related function, `manage_source`, with two public actions, `add_sources` and `delete_sources`, for 1-30 items. Legacy single-item forms are accepted internally for compatibility but are not advertised to the model. Expose it only when the current message contains an explicit add/create/save/store/import/delete/remove request and identifies sources, snapshots, a current source title/ID or the selected source. This conservative server capability gate prevents unrelated edit requests from invoking the source tool; natural-language intent and selection still need the human preview. It prepares one homogeneous validated batch on a copy. Add rows use the same defaults sequentially; reject the entire batch on duplicates, invalid fields or workspace limits. Deletion accepts distinct inventory IDs or exactly one nonempty contains phrase copied from the current request. Resolve contains on ALL saved source titles and full text using literal case-insensitive substring matching, never SQL, regex, semantic matching or retrieved snippets. Empty contains is not a wildcard. Require explicit plural/all scope for multiple filter matches and never broaden an ambiguous single deletion. Tool results contain bounded metadata only, not the full source texts. Confirmation persists all items in one Store.save revision/audit event or none. Require the browser to acknowledge the exact ordered source_ids list for a multi-item batch; IDs cannot change the retained proposal. This prevents older single-preview clients from confirming bulk writes. The app issues an opaque token only after answer/citation/session/revision validation; a separate user-click confirmation endpoint applies shared source helpers. Tokens expire after ten minutes, are bounded to 128 pending proposals, tied to the exact session and revision, and consumed on success. Never expose SQL, arbitrary updates, database connections or confirmation tokens to the model. Questions generation receives only calculate. `frontend/source-actions.ts` validates previews; chat shows metadata, exact text and deletion consequences before applying. App guide, hosted, saved-file and tutorial views must never invoke these writes. Explain unsupported edits while retaining normal read-only answers. Never default to the highest version for deletion without an explicit user selection rule; repeated titles require disambiguation.
- Chat source defaults are next `Source N` among current numbered titles, version `1`, empty URL, `User supplied; verify redistribution rights`, and `No source text supplied for <title>.` for absent text. Preserve supplied text verbatim and normal duplicate/size/hash validation. These defaults are not verified facts or license grants.
- The live Add Evidence form imports six original fictional documents through `POST /api/sources/demo-documents` and `backend/demo_documents.py`: demo/lumenui frontend and demo/harborapi backend, versions 1.0/2.0/3.0 each. The six readable Markdown files and strict manifest live in `data/demo-documents/`. Validate fixed metadata/path allowlists, bounded UTF-8 contents and exact hashes before any write; preserve numeric versions, fictional notices, reserved example.invalid origins and original synthetic MIT attribution. Recheck actor/revision after loading and atomically append nonduplicate sources in one audit/revision. Invalid/missing bundles or capacity failures save nothing. Never make network/model calls or alter existing sources/drafts. Preserve the intentional same-version 2.0 retry_limit disagreement and its 3.0 correction, topic diversity and shared exact identifiers. Graph nodes visibly show versions; relation semantics and Ask Atlas NLP are unchanged. Keep this action out of hosted/tutorial/saved views, and do not replace the separate prepared hosted review. The old backend/demo_readmes.py loader is removed; data/demo-readmes and its notices remain only for existing regression fixtures. Individual public README fetching is unchanged.
- Sources offers pasted source text and public GitHub README fetching. The public GitHub release-feed form is removed from the UI; retain the backend feed endpoint and its integration coverage. Tutorial and contextual help must describe the visible README workflow.
- `backend/readme.py` fetches only public GitHub repository READMEs through three bounded, unauthenticated fixed-host API requests. Verify public visibility, pin the default-branch commit, verify the Git blob hash and preserve exact UTF-8 text. Reject redirects, arbitrary URLs, empty/oversized/invalid content and private repositories. Never forward credentials or follow returned download URLs. `POST /api/sources/readme` returns a draft only, with session/revision checks before and after fetching and one concurrent fetch. `frontend/SourceForm.tsx` and `frontend/readme.ts` handle explicit fetching, stale-result rejection and inline replacement confirmation. Preserve draft metadata and permission fields; saving remains a separate action. Fetching is unavailable in hosted demos, saved files and tutorials.
- Ask Atlas retrieval: `backend/source_context.py` builds a source-hash/title/version/model-keyed, three-entry RAM index independently of saved findings. Parse/coalesce structural blocks into exact-span ~1,000-code-point retrieval windows with 100 overlap, up to 600 candidates; return at most eight passages / 16,000 code points. Fuse subject-weighted TF-IDF lexical matching, pretrained semantic similarity, exact typed entities and explicitly labeled terminology expansion with reciprocal rank fusion. NMF topic memberships/semantic centroids and documentation-purpose classification provide bounded preferences, with at most two strong topic-expansion candidates. Purpose models are fitted on embeddings from the current encoder, never reused across incompatible spaces. Omit unstable/sparse topics. Broad summaries and underspecified count follow-ups use bounded source coverage; ambient selection cannot force irrelevant sources into focused questions. Resolve explicit source/version restrictions conservatively, including commit labels and numeric highest-version requests. Full source inventory and confirmed write tools remain independent of retrieval.
- `backend/retrieval_graph.py` builds the Ask Atlas index's private NetworkX passage/entity graph independently of saved analysis. Resolve unique technology references from distinctive leading project titles with documentation suffixes, or owner/repository README titles; skip generic and ambiguous names. Shared exact technical identifiers must occur in only two or three sources; commands, protocols and generic prose cannot be bridges. Traverse one entity bridge from at most three hybrid seed passages, adding at most two previously unrepresented sources after the first four hybrid candidates. Require query relevance or corroborating seed context for references, and both for shared identifiers. Never recurse, override explicit scope, expand no-match/overview requests, claim a reference establishes integration, or widen the eight-passage/16,000-code-point budget. Preserve conflict-pair packing. Return graph paths only when both exact passages were selected; the browser validates path IDs, source identities, literal bridge support and reason labels. Show paths in existing Retrieved context without adding chat tools or controls. The saved analysis graph remains available alongside the live question graph.
- `backend/semantic.py` runs the pinned Sentence Transformers all-MiniLM-L6-v2 ONNX model through private JSON pipes to `tools/semantic_worker.py`. The optional project-local Python 3.11 environment avoids unsupported Intel Mac/Python 3.14 neural packages; main `.venv` stays Python 3.14. `install-release-atlas-semantic.sh`, `requirements-semantic.txt` and `tools/setup_semantic.py` install pinned dependencies and SHA-256-verified public model artifacts at revision 1110a243fdf4706b3f48f1d95db1a4f5529b4d41. Keep `.tools/semantic/` out of Git/container builds. No runtime download or network listener; the worker receives no provider credentials and does not import database code. Masked mean pooling, normalization and overlapping 256-token windows cover long inputs. Bound IPC, validate vector shapes/finiteness and enforce a 90-second worker deadline. `ATLAS_RETRIEVAL_ENCODER=auto` uses the installed neural encoder; missing/failed/disabled models fall back to explicitly labeled TF-IDF/LSA. Never mix vector spaces after failure. Stop and reap the worker before server connection shutdown; protect simultaneous stop/timeout ownership and prevent restart during shutdown.
- Independent relationship visualization: `frontend/document-relations.ts` and `frontend/RelationshipGraph.tsx` replace the removed linear keyword map and legacy evidence-neighborhood renderer. Keep the existing Ask Atlas NLP, backend graphs, telemetry validation, private streaming and scoped question state untouched. Identify project/source names, rank question relevance and extract only bounded explicit English constructions or corroborated shared capabilities. Never infer a dependency from keywords or disguise historical statements as current facts. Keep exact Unicode source spans/hash evidence, no code/HTML execution or network/model/database calls, a six-node/eight-link cap and honest empty states. `frontend/source-mentions.ts` handles explicit mention/reference/contain questions as bounded, case-insensitive literal matching across selected source bodies, including links/code. Preserve exact Unicode quotes, escaped regex input, term boundaries, up to three terms, simple and/or scope, a six-node/eight-link cap and sparse mention links. Label dotted links as text mentions, never features/dependencies. Single unquoted terms may fall back to genuinely documented related capabilities only with a no-literal-match notice; quoted/exact and negative filters must never silently become positive semantic matches. Generic titles remain eligible source labels. Graph capability rules include routing and Python usage. Language-tagged Python/pycon/py examples may support language or route-decorator evidence only; never execute code or infer dependencies from it. Preserve Unicode boundaries, reject negative capability claims, ignore question filler and require capability support for focused routing/Python maps. Python shared-capability links form a sparse forest and appear only when asked about Python. The static circular SVG, numbered readable list and evidence panel must support keyboard navigation and themes. Use selected source IDs from existing validated reports for question maps, full saved sources for the overview, and retain maps across navigation with existing stale-context guards. Legacy backend graph/connection metadata remains active for retrieval/validation, but is not input to this display. The old `concept-map.ts`, `RetrievalGraph.tsx`, `GraphView`, graph-row tooltips and exclusive styles/tests are removed; do not restore parallel renderers.
- Live question graphs: Graph-page model requests negotiate private `application/x-ndjson` on the existing assistant route. Build context once, validate session/revision before streaming its retrieval report, reuse that exact context for generation, and recheck guards before delivering the final answer or issuing source-proposal tokens. Hold the shared busy lock through the stream; handle cancellation and stream-entry races. Other pages/clients retain JSON. Never put private chat context on shared SSE queues. `frontend/assistant-stream.ts` bounds/decodes frames and `Assistant.tsx` validates reports and progress/final consistency. `question-graph.ts` scopes ephemeral state to request/revision/view/user/workspace; retain it across page navigation and allow an already-started Graph request to finish while another page is open. Clear it on context changes, stop, clear-chat, sign-out and tutorial blocking. Only display it on Graph; returning to Graph restores the retained result. `RelationshipGraph.tsx` uses an independent bounded circular relationship display with exact source evidence. Preserve Show documentation overview, keyboard controls and honest empty states, with no live calls from hosted/saved/tutorial views. ## Correctness boundaries

- Source deletion is revision-checked and audited, through the Sources DELETE route or a confirmed chat source-action POST. Remove dependent findings, their conflict references and saved answers citing them; invalidate graph, topics and analysis while preserving other sources and their review decisions. Sources cards show a labeled delete icon only in live workspaces, with confirmation and busy-state protection. Never enable deletion in hosted demos, saved-file views or tutorials.
- Database security: keep SQL statements fixed and bind every value with placeholders. Never concatenate user/model text into SQL or expose database connections to tools. Runtime `Store.connection()` uses an authorizer allowing only required SELECT/READ/INSERT/UPDATE operations on workspace/saved_workspaces, transactions and json_extract/json_array_length/count. Deny all other capabilities, including DDL, DELETE, ATTACH, unexpected functions and trigger/view-origin operations. Only fixed startup migrations use the private bootstrap connection; never derive that flag from requests. Keep defensive mode, trusted_schema off, extension loading off and SQLite length/statement/parameter/attachment limits. Require Python 3.14 with its supported SQLite configuration APIs. Revalidate full workspaces in atomic writes and keep strict signed-64-bit revisions and validated workspace IDs.
- `backend/input_validation.py` rejects duplicate JSON keys, non-finite constants, invalid UTF-8, nonobject roots and nesting over 64 levels. Guard enforces this within the existing streamed 2 MB request limit, before route handling; source-tool arguments use the same parser. Do not echo raw parser/validation errors. Common Strict models reject invalid Unicode, NUL, C0 controls except tab/CR/LF and DEL; mirror the control rule in frontend imports. Reject invalid data rather than modifying source code or normalizing Unicode, so hashes and quote positions stay exact. SQL/HTML/Python examples must remain inert literal text, not be keyword-filtered or executed.
- Source text retains version, origin, hash and exact Unicode quote positions. Validate references and bounded inputs on import.
- User-supplied usage matches suggest possible relevance; the app does not inspect application source code or prove upgrade safety.
- Default embeddings are statistical TF-IDF/SVD representations. Category scores are uncalibrated. The small synthetic evaluation is not evidence of production accuracy.
- Conflict detection uses conservative rules scoped to the same identifier and version. It is not general contradiction detection.
- Chat source citations use server-created passage IDs, source hashes and exact Unicode offsets. Return quoted source passages from the server, never accept model-generated quote metadata. Validate them again in `frontend/source-citations.ts`, keep them expandable in chat, and preserve original-source navigation. Raw citations must not bypass known conflict-pair checks. Source summaries work without analysis, with zero findings and while old findings are stale; never reuse stale findings.
- Retrieved citations and schema validation do not guarantee that a generated answer is true. Keep supporting passages visible and retain human review.
- Writes require the expected workspace revision. Preserve stale-draft protection, global revisions across workspace switches and per-workspace audit history.
- The current service uses one worker and loopback binding for trusted users. Sign-in is disabled by default; live requests use the audit name `Local reviewer`. Set `ATLAS_AUTH_ENABLED=1` and restart to restore shared-code sessions. Disabled mode must not create access codes or expose sign-in/sign-out controls. Preserve host, origin, input and revision guards in both modes, and session guards when authentication is enabled. Do not silently widen network access.
- Shutdown must close live SSE streams before waiting for connections, with a five-second graceful-shutdown fallback for in-flight requests. Keep Ctrl+C functional while a browser is connected. Validate changes with `tools/shutdown_probe.py`, which uses isolated processes and open SSE clients for SIGINT and SIGTERM.
- Treat document text as untrusted data. Provider credentials belong only in the server environment or a private, Git-ignored repository-root `.env`. `backend/config.py` loads literal single-line `ATLAS_*` and `OPENAI_API_KEY` assignments at startup, without shell execution or interpolation; existing environment variables take precedence. Keep `.env` ignored, use owner-only permissions, and never read or echo user secrets during agent work. The OpenAI provider uses only `https://api.openai.com/v1`, reads `OPENAI_API_KEY` (or an explicit `ATLAS_LLM_KEY` override), requests strict JSON with `reasoning.effort=none` and `store=false`, and preserves local citation/conflict/revision validation. Do not put keys in browser code, snapshots, logs or Git. The Intel Mac launcher loads `.env` before defaults and its optional hidden key prompt. Prompt input is for the current process only and is never saved automatically. Keep the launcher loopback and origin restrictions after loading configuration. A missing key disables model requests with actionable guidance while the review and App guide remain usable.
