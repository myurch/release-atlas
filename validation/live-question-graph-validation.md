# Live question graph validation

Graph-page Model chat submissions request private NDJSON progress on the existing assistant endpoint. Retrieval runs once. The server validates the session/revision before sending the retrieval report, supplies that same context object to generation, and repeats the original session/revision and source-proposal checks before sending the final answer. Other pages and clients retain the existing JSON protocol. No extra generation API call, retrieval request, shared SSE event or database write is introduced.

The browser validates all retrieved passages and graph paths before showing them. The final report must match progress. The Graph page renders supported connections among all selected passages from that report with the existing SVG/CSS approach, source navigation, keyboard controls and expandable supporting quotes. Every selected source is shown once, with supported reference/identifier links regardless of its retrieval method. The display-only connections field is capped at twelve deduplicated source-pair/entity relationships and does not alter ranking, model input or expansion thresholds. Other selected passages remain inspectable without inventing extra relationships. No paths/no matches have explicit empty states. The original analysis graph remains available with Show saved analysis. The graph is not persistent review data and is scoped to the active request, user, workspace, revision and view. It is retained across page navigation, and an existing Graph request can finish while another page is open. Only the Graph page displays it. Frontend regression checks verify away-page completion and restoration alongside stale-context rejection.
